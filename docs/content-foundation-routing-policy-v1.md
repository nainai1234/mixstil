# Content Foundation Routing Policy V1

Status: current content-routing correction

## Problem

The foundational material route must not become the default answer to every
consumer request. Foundational elements are reusable ingredients. Finished
baseline content is the first-result quality surface for broad user needs.

If the runtime treats candidate foundational materials as the primary product
for generic Sleep, Calm, or Focus requests, two things go wrong:

- the user hears ingredient-level combinations when they expected a finished,
  save-worthy result;
- inventory counts become misleading, because configured or candidate materials
  are mistaken for complete product content.

## Correct routing

```text
generic user need
  -> finished/internal baseline seed when available
  -> save/replay/refine

explicit element-level need
  -> foundational element route
  -> Recipe V2 arrangement
  -> save/replay/refine

missing element family
  -> block or route to production gap
  -> do not pretend a candidate is formal usable
```

## Generic request examples

These should prefer finished/internal baseline seeds:

- “晚上睡不好，想安静下来”
- “下午要工作，给我适合专注的声音”
- “我有点焦虑，想放松一下”

## Element-level request examples

These may use foundational element routing:

- “想听很轻的雨声，不要人声、不要鼓点”
- “只要安静底层和遮蔽，不要音乐、不要水声、不要公路感”
- “有一点稀疏钢琴感，但不要明显旋律”
- “不要旋律，只要写代码时遮蔽干扰”

## Current inventory truth

The current business audit says the foundational baseline is not complete:

- configured foundational audio items: 179
- candidate foundational audio items: 176
- machine-passed foundational audio items: 167
- formal usable foundational audio items: 14
- gap to internal target: 66

So the product can keep using the foundational route for internal, explicit
element-level requests, but it must not treat this as a complete foundational
inventory.

## Next content work

Promote candidate families into formal usable foundational elements by family:

1. environment identity beds;
2. music beds and phrases;
3. organic textures;
4. accent and transition events;
5. playable instrument sources that passed runtime proof.

Finished seed content remains separate and must not be counted as foundational
elements.
