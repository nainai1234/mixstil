# 个性化冥想声景分享与自传播机制研究

日期：2026-07-13  
状态：已被 [分享自传播机制 V2](./sharing-self-propagation-mechanism-v2-2026-07-13.md) 替代  
适用主线：Recipe V2 冻结作品后的分享、复听与反馈闭环

## 1. 结论先行

SNOOZE 不应只做一个“分享按钮”，也不应把两类用户拆成两套产品。应在同一份冻结作品之上，提供两种明确的分享意图：

1. **分享给朋友**：普通用户表达关心、分享此刻的状态，或送出一段声音。
2. **交付给客户**：冥想老师、瑜伽老师、声音疗愈师和陪伴型创作者，把声景作为一次服务的延伸交付。

接收者打开后都应立即播放，但页面语境、身份、隐私、反馈和后续动作不同。真正的传播闭环不是：

```text
制作 -> 复制链接 -> 结束
```

而是：

```text
描述需求 -> 得到并确认声景 -> 冻结 Recipe Version
  -> 选择“分享给朋友”或“交付给客户”
  -> 接收者无需注册即可播放
  -> 接收者获得当下价值并作轻反馈
  -> 点击“为我生成一段”创建自己的个性化版本
  -> 保存并再次分享
```

产品的传播单元应是“一个可立即体验、可追溯来源、可生成个人版本的声音处方卡”，不是 MP3 文件，也不是平台宣传卡。

## 2. 调研方法与样本

本次优先核验产品官方页面和官方帮助中心，覆盖四类可比产品：

- 冥想与健康内容：Insight Timer、Calm。
- 可调整声景：myNoise。
- 使用后有结果感的消费产品：Strava、Spotify Wrapped。
- 专业内容交付工具：Loom、Practice Better。
- 可复制创作工具：Canva。

这些产品没有一个能被整体照搬，但它们分别验证了分享机制中的不同环节。

## 3. 市场机制拆解

| 产品 | 已核验的分享机制 | 为什么用户愿意分享 | 对 SNOOZE 的启发 |
| --- | --- | --- | --- |
| myNoise | “Save to URL”把用户调好的全部声音参数写进 URL；链接可收藏、分享，别人打开即可听到同一设置 | 分享的是可直接使用的体感，不是产品介绍 | Recipe Version 必须随链接稳定复现；打开链接不应重新生成随机结果 |
| Insight Timer | 每个内容有可分享链接；教师后台提供 Promotion、渠道链接和点击分析；直播中可插入课程卡；新订阅可带来推荐奖励 | 分享同时带来专业影响力、学生和业务结果 | 服务者需要品牌身份、渠道归因、完播反馈和后续服务 CTA，而不只是播放量 |
| Calm | 订阅用户可送出 30 天 Guest Pass，让朋友先完整体验 Premium | 赠送有明确接收价值，且不要求发送者写营销文案 | 奖励应是“送体验”或“解锁一次个性化生成”，而不是早期现金裂变 |
| Strava | 活动完成后生成带地图、照片和核心数据的分享图，可直接发到 Instagram、WhatsApp、短信和邮件 | 结果卡同时表达成就、身份和故事 | 声景分享卡需要表达“为谁、为何刻、什么声音”，但不能公开敏感情绪推断 |
| Spotify Wrapped | 把个人数据故事做成逐张可分享卡；每张都能直接进入系统分享 | 每张卡都是身份表达和社交谈资 | 可以做“本周最常回到的声音”“我的夜间声景”，但应放在有真实复听数据之后 |
| Loom | 作品链接可直接交付；观看者数据和参与度回流；页面可配置 CTA，引导预约、购买或查看更多 | 分享是完成工作和推动下一步，而非替工具拉新 | 客户交付页要让服务者完成服务闭环：播放、轻反馈、预约/下一次练习 |
| Practice Better | 服务者把任务和资源放进客户 Portal，客户持续访问材料、模块和记录 | 内容被纳入持续服务关系，而不是一次性散落链接 | 专业版需要客户列表、分配、计划、到期时间和回访，不应只有公开主页 |
| Canva | Public view link 用于查看；Template link 让接收者基于原设计创建自己的副本；原件与副本分离 | 接收者不只消费，还能马上拥有并继续创作 | “为我生成一段”应克隆模板/意图边界，不复制发送者的私人描述和身份数据 |

### 3.1 共同规律

愿意分享的产品通常同时满足五点：

1. **接收者立即得益**：打开就能听、看或使用，注册放在价值发生之后。
2. **发送者获得表达或工作价值**：表达关心、展示身份、完成交付、获得反馈或承接业务。
3. **分享结果足够具体**：不是“来试试这个 App”，而是“这是我为你做的 10 分钟雨夜呼吸声景”。
4. **结果可以被稳定重现**：同一个链接不能因为重新生成而变成另一段体验。
5. **接收者有自然的下一步**：收藏、回应、生成自己的版本、继续课程或预约，而不是被强制下载 App。

### 3.2 不应照搬的机制

- 不用“分享 3 人解锁功能”作为首发核心。冥想和情绪场景天然私密，强制裂变会伤害信任。
- 不以现金推荐奖励启动普通用户传播。先证明接收者愿意播放和生成自己的版本。
- 不公开“焦虑、失眠、创伤”等系统推断作为社交卡标题。
- 不让分享页变成平台广告落地页。接收者首先是来听一段声音。
- 不把 MP3 下载当主传播路径。文件失去版本、来源、反馈、权限和二次生成入口。

## 4. 产品对象：一份作品，三种可传播载体

### 4.1 Frozen Listening Link：冻结试听链接

所有分享的底层对象。必须绑定：

- `mix_id` 与 `published_recipe_version_id`。
- 已渲染音频或与冻结 Recipe 等价的 Live Mix。
- 授权与 QA 快照。
- 创建者、标题、封面、时长和安全标签。
- 可撤销的稳定 slug，而不是暴露内部 ID。

链接打开后：无需登录、一个主播放按钮、首屏不弹注册、不自动播放。

### 4.2 Care Share：送给朋友的声音卡

发送者可选：

- “想到你，所以把这段声音送给你。”
- “这是我今晚在听的声音。”
- “我们一起听 10 分钟。”
- 自定义一句短留言。

接收者页面顺序：

```text
来自谁 + 一句话
  -> 立即播放
  -> 适合我 / 想更安静一点 / 稍后再听
  -> 收藏此版本
  -> 为我生成一段
```

公开社交卡只展示用户主动填写的信息。系统识别出的情绪、睡眠问题和排除项默认不出现在图片、Open Graph 标题或 URL 中。

### 4.3 Client Delivery：客户交付卡

服务者在发布时补充：

- 客户显示名或匿名称呼。
- 使用场景，例如“今晚睡前”“课后 7 天练习”。
- 服务者说明和建议使用时长。
- 可用起止时间、是否允许下载、是否允许生成个人副本。
- 服务者品牌、头像和合规范围内的后续 CTA。

客户页面顺序：

```text
服务者身份 + 本次练习说明
  -> 立即播放
  -> 完成 / 未完成
  -> 可选轻反馈：太强、刚好、太弱；想更少人声
  -> 下次继续 / 预约 / 联系服务者
  -> 经允许后“基于这份为我调整”
```

这不是医疗处方，不记录诊断或疗效承诺。反馈用于声音偏好和服务跟进，不用“治愈率”“焦虑降低”等医疗化指标。

## 5. 自传播引擎

### 5.1 核心动作：为我生成一段

每个外部分享页在产生有效试听之后，提供唯一主要增长 CTA：

> 喜欢这段感觉？说说你现在需要什么，为你生成一段。

点击后：

1. 继承可公开的目标、模板族和听感特征。
2. 不继承发送者原始 Prompt、私人留言、客户姓名或敏感意图字段。
3. 进入 Quick Create，先问一句当前需求，再生成新的 AudioIntent。
4. 生成全新的 Recipe、所有权和冻结版本。
5. 新用户听到结果后才提示保存账号。

这对应 Canva 的 Template Link，但复制的是安全的“创作起点”，不是复制私人作品本身。

### 5.2 传播激励

普通用户的激励：

- 每月可送出若干张“个性化声音礼物”。
- 当接收者完成一次有效试听，发送者获得一张新的礼物额度或一个非核心封面样式。
- 不以点击或联系人数量发奖励，避免垃圾传播。

服务者的激励：

- 免费完成基础客户交付。
- Pro 解锁品牌页、客户计划、渠道归因、批量分配、播放趋势和 CTA。
- 当客户生成自己的版本时，来源仍归因到服务者，但新作品归客户所有。

接收者的激励：

- 无需注册即可完整试听发送者指定的作品。
- 首次可免费生成并保存一个自己的短版本。
- 不用转发才能继续使用。

### 5.3 传播卡与渠道

同一作品生成不同渠道资产：

- 私聊：带发送者留言的链接预览。
- 朋友圈/Instagram Story：9:16 静态或 10–15 秒有声预览，包含标题、声景元素和二维码。
- 小红书/Feed：4:5 封面，强调使用场景，不做疗效承诺。
- 线下课程：可撤销二维码，直接进入客户交付页。
- 服务者网站/Newsletter：可嵌入播放器和来源参数。

原生分享优先使用 Web Share API；没有原生分享时再提供复制链接和按渠道生成素材。渠道按钮不是机制本身，只是分发出口。

## 6. 数据模型与事件漏斗

不能继续只在 `mixes.share_clicks` 上加一。至少需要三个对象：

```text
share_packages
  id, mix_id, recipe_version_id, mode, slug, creator_id,
  recipient_label, message, visibility, expires_at,
  allow_download, allow_remix, cta_type, cta_url, revoked_at

share_attributions
  package_id, channel, campaign, referrer_creator_id,
  anonymous_visitor_id, converted_user_id

share_events
  package_id, visitor_id, event_type, elapsed_ms,
  playback_seconds, source, created_at
```

完整事件：

```text
share_started
-> share_package_created
-> native_share_opened / link_copied / asset_downloaded
-> landing_opened
-> playback_requested
-> playback_started
-> meaningful_listen
-> recipient_feedback
-> remix_started
-> new_recipe_ready
-> new_work_saved
-> new_work_shared
```

`meaningful_listen` 首版建议定义为满足任一条件：

- 播放达到作品时长的 50%；
- 对长作品连续播放达到 5 分钟。

分享奖励、来源归因和北极星指标只使用有效试听或更深事件，不使用复制链接次数。

## 7. 指标体系

### 北极星指标

> 每周由外部分享带来的有效试听人数。

### 自传播指标

- 分享作品率：保存作品中创建分享包的比例。
- 首次分享时间：首次保存到首次创建分享包的时间。
- 分享到有效试听转化率。
- 有效试听到“为我生成一段”转化率。
- 新版本保存率。
- 接收者 7 日复听率。
- 接收者再分享率。
- Activated K-factor：每名分享者带来的“完成有效试听并保存自己版本”的新用户数。

### 服务者指标

- 客户交付创建数和送达率。
- 客户首次播放时间。
- 有效试听率和重复练习率。
- 轻反馈响应率。
- CTA 点击率。
- 服务者 4 周留存与每周活跃客户数。

不要把“分享点击数”“生成海报数”或“总注册数”作为主成功指标。

## 8. 与当前产品的差距

当前实现已经具备：

- `/work/:id` 公开作品页。
- Web 链接复制、WhatsApp 和 Reddit 出口。
- 海报和短视频的付费占位。
- `share_clicks`、收藏和部分播放数据字段。
- Recipe Version 冻结、渲染和授权检查主干。

但当前缺口会阻断自传播：

1. 分享页直接使用内部 `mix id`，没有独立、可撤销、可到期的分享包。
2. 公开传播与客户交付没有模式和权限差异。
3. UI 的复制链接和外部渠道动作没有调用 `api.recordShare`，现有分享计数不能代表真实分享。
4. 后端只累计 `share_clicks`，无法区分渠道、打开、播放、有效试听、生成副本和再分享。
5. 外部接收者页面仍出现“My Library”等创作者语境，且提供服务端渲染/下载入口，角色边界不清。
6. 没有“为我生成一段”的 Recipe 派生入口。
7. 没有客户称呼、说明、有效期、下载权限、反馈或服务者 CTA。

## 9. 分阶段落地

### P0：当前小流量验证，1 个 Sprint

只做当前主线所需的最小闭环：

- 冻结版本生成独立 share package 和稳定 slug。
- 发布时选择“分享给朋友”或“交付给客户”。
- 两种接收页都无需登录、点击后立即播放。
- 接入 Web Share API、复制链接和渠道参数。
- 建立从创建分享包到有效试听的完整事件。
- 接收页增加“为我生成一段”，跳回 Quick Create。
- 权利、QA、撤销和过期检查在分享入口统一执行。

P0 退出标准：

- 10–20 名目标用户完成真实分享。
- 至少收集 30 次外部打开和 10 次有效试听。
- 能回答每个渠道的打开率、首播率和有效试听率。
- 至少观察到 3 次接收者进入 Quick Create；此处是探索门槛，不是规模结论。

### P1：验证服务者付费价值

- 服务者品牌、客户列表和客户交付历史。
- 使用说明、到期时间、下载/派生权限。
- 轻反馈、重复练习和渠道分析。
- 单一合规 CTA：预约、加入下一次课程或访问服务者主页。
- 二维码海报和短试听素材。

### P2：数据成立后再做

- 7/14/30 天练习计划和定时交付。
- 系列、批量客户分配、团队协作和 CRM 集成。
- 复听数据形成的个人回顾卡。
- 经过反作弊验证的推荐奖励。
- 平台精选与创作者商业分成。

当前不要做复杂社区、评论、私信、现金裂变或通用白标 App。这些都晚于“分享带来有效试听和新版本保存”的证明。

## 10. 首轮实验

### 实验 A：分享意图

对比普通“复制链接”与发布后的二选一：

- 送给朋友。
- 交付给客户。

观察分享包创建率、发送率和有效试听率。

### 实验 B：接收页 CTA 时机

- A 组：打开即展示“为我生成一段”。
- B 组：有效播放 60 秒后展示。

预期 B 组注册更少但生成意愿更真实。以新版本保存率判断，不以 CTA 点击率判断。

### 实验 C：客户交付信息

- A 组：作品页只有创作者身份。
- B 组：增加客户称呼、练习说明和服务者 CTA。

观察首播率、重复练习率和 CTA 点击率。

### 实验 D：传播奖励

- A 组：无奖励。
- B 组：接收者完成有效试听后，发送者增加一张声音礼物额度。

观察有效试听和举报率，不使用“分享人数”作为奖励条件。

## 11. 产品决策

建议把分享机制的产品定位确定为：

> 让个人把一段声音作为关心送出去，让服务者把一段声音作为专业服务交付出去；每个接收者都能先获得真实体感，再自然生成属于自己的版本。

这保留了当前 creator-tool-first 的商业逻辑，同时把普通自用用户纳入同一条增长链。平台品牌应存在于“Powered by SNOOZE / 为我生成一段”的轻入口，而不是抢占作品和服务者身份。
