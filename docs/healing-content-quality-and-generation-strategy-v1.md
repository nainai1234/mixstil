# 疗愈声景质量标准与生成能力策略 V1

日期：2026-07-12  
状态：产品与内容放行基线

## 1. 核心判断

行业没有统一、公开、经过验证的“疗愈音频通用标准”。不能用单个创始人的听感、YouTube 标题、432Hz 标签或某个竞品的宣传证明内容有效。

DeepNill 采用四层证据体系：

1. 研究证据：只支持保守表述，例如音乐和自然声可能帮助建立低干扰环境，不承诺治疗。
2. 市场结构：参考 Headspace、Calm、BetterSleep、Endel、myNoise、Brain.fm 的内容分类和阶段组织。
3. 工程质量：响度、峰值、动态、突发声、循环接缝、频谱冲突和长时间疲劳必须可测。
4. 用户结果：首次接受、调整后保存、复听、分享和负面原因决定内容是否继续使用。

只有四层都没有阻断问题，内容才可以标记为适合目标场景。产品文案使用“为睡前/放松/专注设计”，不使用“保证助眠、提高专注、治愈焦虑”。

## 2. 内容模式质量基线

### 2.1 纯声景

- 不自动加入音乐或人声。
- 不出现突发雷声、近距离鸟叫、明显水滴或其他抢注意力事件，除非用户明确要求。
- 循环接缝不可感知，长时间重复不能形成明显节拍。
- 用户排除水声、鸟声或人声时必须严格执行。

### 2.2 功能音乐

- 音乐承担主要结构，但默认低刺激、低动态。
- Focus 默认整体层级低于娱乐音乐，不能用“Focus”标签替代真实响度控制。
- 避免歌词、明显主旋律、强打击和频繁和声转折。
- 环境层只能轻微辅助，不能与音乐同时抢前景。

### 2.3 声音旅程

- 必须存在 Arrival / Core / Release，而不是多条循环轨道同时播放到底。
- 阶段主次随时间变化；自然声、音乐和底层不能一直同响同大。
- 转场使用淡入淡出和音量自动化，不能突然切换。

### 2.4 引导冥想

- 前段短句引导，句间留白，后段人声退出。
- 首版工程目标：连续发声 3-8 秒、句间停顿 3-10 秒、人声占比约 15%-45%。这些是实验指标，不是医学标准。
- 人声母版约 -28 LUFS，峰值不高于 -6 dBTP；背景在人声出现时 Ducking，结束后平滑恢复。
- 脚本禁止诊断、保证疗效、服从暗示和高风险催眠表达。

### 2.5 ASMR

在正式建模前分为：无语言触发、近讲/耳语、角色会话。三者不能共用一个模糊的 `asmr` 标签。没有专用近场素材、双耳空间和事件密度规则前，只允许作为内部实验。

## 3. 放行机制

每个公共素材和默认 Recipe 必须经过：

1. 来源、许可、二创、公开分享和付费使用核对。
2. 解码、采样率、时长、响度、峰值、静音和瞬态自动检查。
3. 循环接缝、层级平衡、疲劳和场景匹配的专业或半专业听感审核。
4. 目标用户盲测，不告诉用户“这应该助眠/专注”，只问是否愿意继续听、保存或复听。
5. 小流量行为验证；高调整率、高退出率或重复负面反馈会自动降级为 `needs_review`。

单个普通用户可以否决明显失败，但不能单独证明内容适合公开放行。

## 4. 外部生成能力的正确位置

外部 API 分成两条管线。

### 4.1 后台一次性资产生产

用于补充高频缺口。每个缺口生成多个候选，经过完整 QA 后进入公共素材库。成本只发生在生产阶段，之后由所有用户复用。

优先用途：

- 特殊环境声和稀缺音效。
- 转场、点缀、ASMR 触发候选。
- 缺少的 Pad、Drone 和低刺激功能音乐。
- 生产级中英文引导人声。

候选 Provider：

- ElevenLabs Sound Effects：特殊音效和环境声候选，一次生成多个版本。
- Stability AI / Stable Audio：音乐、Pad、Drone 后台候选；采用时锁定具体模型和许可版本。
- Mubert：按用途和时长生成音乐候选；必须选择允许产品组合、导出和分发的许可。
- Azure Speech、Google Cloud TTS、Amazon Polly、ElevenLabs TTS：生产人声质量与成本对照。

任何 Provider 的“royalty-free”都不自动等于允许原样再分发、组合进付费作品或永久公开分享。每次采用必须保存计划、条款日期、模型、Prompt、输出 Hash 和成本。

### 4.2 Pro 按次实时生成

只在公共库无法满足用户明确需求时调用，例如独特音乐、特殊环境、定制时长或高质量个性化人声。

计费基础：

```text
预计费用 = 音乐生成秒数 + 音效调用 + TTS 字符/秒数 + 渲染 + 存储
```

- 生成前显示预计额度或时长成本。
- 失败、超时或质量不合格不扣除完整额度。
- 用户取消时不继续调用供应商。
- API 失败必须回退到内部素材 Recipe。
- 未通过技术和许可门槛的实时结果不能直接公开发布。

## 5. Provider 路由顺序

```text
审核公共素材
-> 已生成但未公开的候选库
-> 本地可控合成
-> 后台外部 API 生成候选
-> Pro 实时生成
```

不是所有请求都调用外部 API。基础版靠公共素材快速首播；Pro 为真正独特、公共库无法覆盖的部分付费。

## 6. 商业产品分层

### Free / 基础版

- 审核公共素材和默认 Recipe。
- 三个目标与基础内容模式。
- Live Mix、简单调整、保存和分享。
- 少量标准人声或无人声模式。

### Plus

- 更多审核模板、素材和更长时长。
- 高质量生产 TTS 额度。
- 高质量导出、更多作品和品牌化分享。

### Pro

- 按生成秒数或额度调用音乐、音效和高级人声 API。
- 高级 Recipe 编辑、版本、批量生产和数据分析。
- 每次生成保留成本、模型、授权和可复现记录。

## 7. 下一阶段执行顺序

1. 建立研究和市场样本的统一结构表，不再用标题推断音轨结构。
2. 将上述模式质量标准写入自动 QA 和听感 QA 表。
3. 邀请至少一名冥想内容从业者和一名音频工程人员做第一轮盲审。
4. 使用 10-20 名目标创作者完成描述、试听、调整、保存和分享。
5. 汇总高频失败和素材未命中，形成缺口排行。
6. 只对排行前 3 的缺口运行一次性 API 生产实验。
7. 测量候选可用率、单条成本和授权通过率，再决定 Plus/Pro 实时能力。

## 8. 当前产品结论

当前系统是真实可运行的素材选择、Recipe 编排、Live Mix、冻结和渲染系统，但不是经过临床或大规模用户验证的疗愈系统。现有内容可以用于产品实验；在通过专业审核和真实用户结果验证前，不能宣称它“适合所有人”或具有确定的助眠、专注和治疗效果。
