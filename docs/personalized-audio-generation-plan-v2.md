> 和 [Project Mainline Charter](./project-mainline-charter.md) 为最高指示。

## 当前发布范围（2026-07-13 决策）

首个验证版本先发布 **Voice-free Beta**。Beta 只承诺用已审核的环境声、噪声与音乐完成个性化声景；TTS 和引导人声暂不进入用户产品。

执行边界：

- `AudioIntent V2` 继续识别人声诉求，但运行时必须降级为 `voice_off`，并保留这一决策供后续分析。
- `Recipe V2`、Live Mix、冻结版本、最终渲染和分享页在 Beta 中只能包含可听的非 Voice 轨。
- 历史 Voice 轨必须在播放端过滤，并在发布检查中 fail closed。
- 前端不显示人声、TTS、录音或占位式引导控件，避免承诺尚未达到质量标准的能力。
- 生产级中英文 TTS 是完整版本的后续放行门槛，不阻塞无人声 Beta 的小流量验证。

无人声 Beta 的成功标准仍然是“描述到满意结果”：用户能在几秒内听到贴合需求的结果，进行局部修改，保存、冻结、渲染并分享，而不是只证明系统能播放已有素材。

项目级执行约束：[个性化音频项目主线宪章](./project-mainline-charter.md)。当局部需求与本方案主线冲突时，以主线宪章和本方案的 Sprint 顺序为准。

需求理解、素材本体、语义检索、组合求解与供给缺口的下一阶段设计见：[个性化音频智能架构 V3](./personalized-audio-intelligence-architecture-v3.md)。V3 不替代 Recipe V2 的可复现执行模型，而是在其前面补齐需求端与供给端智能。

## 1. 重新调研后的结论

V1 的“需求理解 + 配方组合 + 能力路由”方向成立，但执行顺序仍然偏重生成技术。竞品复核后，V2 做出五项调整：

1. 首版不为每个请求实时生成音乐或自然声。
2. 将“后台资产生产”和“用户前台创作”分成两条管线。
3. 将五个平级场景收敛为三个一级目标、五个二级场景。
4. 将输出明确分为实时 Mix 和冻结后的可分享 Work。
5. 先验证“快速得到满意结果”，再验证本地音乐模型和复杂自适应能力。

新的一句话定位：

> 用户描述自己此刻需要的声音，系统用经过审核的声音和可控人声，在几秒内做出一段可调整、可保存、可分享的个性化声景。

这不是通用 AI 音乐生成器，也不先做大而全的睡眠订阅 App。产品差异仍然是：

```text
自然语言低门槛创作
  + 场景化声音配方
  + 可调整的多层声景
  + 引导人声
  + 作品分享和数据反馈
```

## 2. 竞品实际怎么做

### 2.1 Endel：实时 Soundscape 与定时 Scenario 分离

Endel 官方将内容分为两种：

- Soundscape：根据时间、天气、位置、步行节奏、心率等输入在设备上持续生成。
- Scenario：具有预先定义的开头、中段和结尾逻辑，按用户设置的时长运行。

其核心不是让用户写 Prompt，而是减少决策：选择 Focus、Relax、Sleep 等目标后立即播放。Autoplay 还会替用户选择当前模式。

对我们的启发：

- “无限播放”与“结构化作品”必须是两个对象。
- 首版不需要复制天气、心率和昼夜节律输入。
- 用户想立即听时，不应该等待完整 MP3 渲染。
- 结构化冥想必须有阶段，不是把几个循环音轨平铺到底。

不应照搬：

- 生物指标和科学效果宣传需要研究、合规与设备生态支撑。
- Endel 是听众订阅产品，我们仍以轻创作者和分享闭环为先。

### 2.2 BetterSleep：大素材库 + 自由混音 + 编辑内容

BetterSleep 官方首页把产品分成三类内容：

- 可自由组合的自然声、噪音、脑波和人声片段。
- 专业制作的冥想、催眠和 SleepTales。
- 睡眠音乐与播放列表。

它的用户价值不是 AI 从零生成，而是“我能混出适合自己的声音”，同时在不想创作时直接消费专业内容。

对我们的启发：

- 素材选择和音量控制是长期有效的核心能力。
- 引导冥想与故事属于编辑内容生产，不应全部依赖即时生成。
- 免费素材降低上手门槛，完整素材库和长内容可以成为订阅权益。

不应照搬：

- 首版不追求庞大目录。
- 对频率、脑波和疗效相关文案采取更保守的合规策略。

### 2.3 myNoise：少量高质量录音 + 多频段参数化

myNoise 将自然录音、氛围音乐和噪音拆成可调声部，通过多段滑块、频谱塑形和滑块动画形成持续变化的声音环境。页面明确强调声音是可调整、不中断且保持一致的。

它证明“生成感”不一定来自生成模型，也可以来自：

- 多个协调 Stem。
- 频段和音量参数。
- 缓慢、确定性的参数变化。
- 场景化预设。

对我们的启发：

- 资产的兼容性和参数元数据比素材数量更重要。
- 可以先用确定性自动化创造“持续变化”，无需实时生成新音频。
- 核心素材应提供推荐音量范围和频谱角色。

版权边界：myNoise 页面标注其内容仅供个人使用，不能把其音频当成我们的可用素材来源。

### 2.4 Brain.fm：卖的是功能目标，不是创作自由

Brain.fm 将产品描述为用于 Focus、Relax 和 Sleep 的 functional music。用户主要选择目标和会话，而不是处理音轨。

对我们的启发：

- 用户入口应以“我要达到什么状态”为主，而不是“我要添加什么 Stem”。
- 复杂参数应放在结果页和高级编辑器，而不是首屏。
- 功能场景必须通过实际留存和完成数据验证，不能只靠技术标签成立。

### 2.5 Headspace：专家内容库 + 推荐，而非即时生成冥想

Headspace 的公开产品仍以专家引导冥想、睡眠音乐、白噪音和主题内容库为核心。其 AI 入口 Ebb 在首页描述为个性化内容推荐，而不是自动生成并发布完整冥想内容。

对我们的启发：

- 高风险的人声引导应从审核过的脚本骨架开始。
- AI 更适合先做推荐、改写和个性化填充，不应自由发挥完整“治疗式”脚本。
- 生成内容和专家/编辑内容应有清晰标识。

### 2.6 Mubert：Prompt + 类型 + 时长的音乐生成

Mubert Render 将流程收敛为三个参数：输入英文 Prompt、选择 Track 类型、设置时长，然后生成 royalty-free music。它同时提供大量用途和风格播放列表。

对我们的启发：

- 即使是生成音乐产品，也不会把所有工程参数暴露给用户。
- Prompt 之外仍需要类型、时长等确定性控制。
- 生成结果必须与具体许可证绑定。Mubert 页面底部同时说明站内播放音乐默认仅限个人使用，公开使用需要匹配正确许可，不能把“royalty-free”理解为任意再分发。

### 2.7 ElevenLabs：适合缺口生成，不适合替代核心自然声库

ElevenLabs 官方 Sound Effects 产品支持文本生成音效与环境音，一次返回四个候选，并提供 API。官方页面将其定位为影视、视频、游戏等生产素材。

对我们的启发：

- 外部音效生成应一次生成多个候选，再经过筛选和 QA。
- 更适合生成特殊场景、转场和点缀音。
- 雨、海浪、河流等长时间核心底层仍优先使用授权实地录音。
- “Royalty free”仍要按账号套餐、API 条款和允许的分发方式留存许可快照。

### 2.8 Stability AI：模型版本与许可变化快，不能写死技术路线

Stability AI 的公开页面显示 Stable Audio 产品和许可持续迭代；搜索结果已出现 Stable Audio 3.0、Open Small 和不同 Community/Enterprise 许可边界。旧的 Stable Audio Open 不应被写成唯一指定方案。

对我们的启发：

- 模型选型必须是可替换 Adapter。
- 在采用模型时记录精确模型版本和当时许可。
- 本地模型只用于后台资产生产 Spike，不进入首版用户实时路径。

市场空位不是“再做一个 Endel”或“再做一个 BetterSleep”，而是：

> 把 BetterSleep 的可组合性、Endel 的场景结构、Headspace 的内容安全，与创作者作品分享和数据反馈结合起来。

## 4. V2 产品结构

### 4.1 三个一级目标

首版只让用户先选择三个目标：

- 睡眠 Sleep
- 放松 Calm
- 专注 Focus

系统再从描述中识别五个二级场景：

| 一级目标 | 二级场景 | 首发支持 |
| --- | --- | --- |
| Sleep | 睡前入睡 | 是 |
| Sleep | 夜醒回睡 | 是 |
| Calm | 冥想呼吸 | 是 |
| Calm | 情绪放松 | 是 |
| Focus | 专注工作 | 是 |

这样既保留 V1 的五类配方，又把用户入口降到三个稳定心智。

### 4.2 两种输出对象

#### Live Mix

- 几秒内开始播放。
- 由已审核 Stem 在客户端或服务端实时组合。
- 支持音量、强度、时长和人声开关。
- 不要求先渲染完整文件。
- 用于快速验证用户是否喜欢结果。

#### Published Work

- 将用户确认的配方冻结为版本。
- 点缀事件、人声时间码和随机种子固定。
- 服务端渲染为 MP3/AAC，保留母版。
- 拥有标题、封面、分享页和数据指标。
- 只有通过授权与质量门槛后才能公开。

转换流程：

```text
描述需求 -> 立即得到 Live Mix -> 局部调整 -> 保存配方
  -> 用户选择发布/下载 -> 冻结版本 -> 服务端渲染 -> Published Work
```

### 4.3 三层用户界面

第一层：快速开始

- 目标：Sleep / Calm / Focus。
- 一句话描述，可跳过。
- 时长。
- 有无人声。
- 立即生成。

第二层：简单调整

- 环境声选择。
- 环境、音乐、人声三个强度控制。
- 人声语言与音色。
- “更温暖 / 更安静 / 更有空间感”等可理解选项。

第三层：高级工作台

- 多轨时间轴。
- Stem 替换、裁剪、淡入淡出。
- 人声脚本编辑。
- 点缀事件编辑。
- 版本、导出和分享。

这保留创作者工具价值，同时避免新用户被复杂混音器挡住。

## 5. 内容生产策略

### 5.1 前台与后台严格分离

前台请求允许实时发生：

- 意图解析。
- 素材检索与配方组合。
- 参数自动化。
- 经审核脚本骨架的个性化填充。
- 付费额度内的 TTS。

后台内容工厂负责：

- 新自然声采购和导入。
- 新音乐、Pad、Drone 和点缀音生成。
- 多候选筛选。
- 授权、技术 QA、听感 QA。
- 晋升为公共 Stem。

首版禁止前台请求即时生成音乐后直接发布。这一规则同时降低等待时间、成本、质量和版权风险。

### 5.2 首发核心包缩减为 18–24 个 Stem

V1 的 24–30 个并非错误，但对第一轮验证仍偏多。V2 的最小核心包：

| 类别 | 数量 | 内容 |
| --- | ---: | --- |
| Noise | 4 | 柔白、柔粉、深棕、柔棕 |
| Nature | 6 | 轻雨、长雨、海浪、河流、微风、火焰 |
| Music | 4–5 | 温暖 Pad、深 Drone、透明 Pad、稀疏钢琴、可选音钵 |
| Accent | 2–3 | 柔和钟声、水滴、低频音钵 |
| Voice | 2 个脚本族 × 中英文 | 睡前/夜醒、呼吸/放松 |

核心包要求：

- 每个非 Voice Stem 至少能进入两个二级场景。
- 每个场景至少有两个明显不同但稳定的默认组合。
- 先用现有资产完成，不足部分才生成或采购。

### 5.3 人声采用“脚本块”而不是整篇自由生成

脚本拆成审核过的模块：

```text
开场许可 -> 姿势/安全提示 -> 呼吸或身体觉察
  -> 场景核心段 -> 长停顿 -> 结束或进入无人声阶段
```

LLM 首版只能：

- 选择脚本块。
- 调整称呼、长度、语气和场景细节。
- 在白名单表达范围内改写。

LLM 不能：

- 诊断用户。
- 承诺效果。
- 自由添加催眠暗示、创伤处理或危险呼吸指令。

## 6. 技术架构修订

### 6.1 前台生成路径

```text
用户输入
  -> AudioIntent V2
  -> Theme + Template 选择
  -> Stem 检索与兼容性评分
  -> Recipe V2
  -> Live Mix 立即播放
  -> 用户修改
  -> 冻结 Recipe Version
  -> 授权检查
  -> ffmpeg 渲染
  -> Published Work
```

首版的 AI 只负责把开放描述转换为受约束的结构化字段。配方由确定性规则生成，保证可测试和可复现。

### 6.2 后台资产生产路径

```text
资产缺口清单
  -> 选择采购 / 录音 / 本地模型 / 外部 API
  -> 每个需求生成或收集 4–10 个候选
  -> 自动技术 QA
  -> 人工短名单试听
  -> 许可确认
  -> approved Stem
  -> 加入主题和兼容性规则
```

本地模型和 ElevenLabs 等供应商都只是一种 Producer，不进入业务对象核心。

### 6.3 循环与持续变化

不要要求模型一次性产生完美 Loop。V2 采用三层策略：

1. 入库时选择和裁切可循环区间。
2. 渲染时使用可配置交叉淡化，具体秒数由素材类型决定，不统一写死 3–5 秒。
3. 对部分 Stem 使用缓慢增益、声像或滤波自动化，降低重复感。

客户端 Live Mix 和服务端导出必须共享同一 Recipe 语义；允许实现不同，但听感结构不能明显不一致。

### 6.4 自动 QA

第一版优先复用 `ffmpeg`：

- `astats`：峰值、RMS、动态范围、直流偏移。
- `ebur128`：响度和 True Peak。
- `silencedetect`：异常静音。
- `volumedetect`：快速电平检查。

第二阶段再使用 Python/librosa：

- 接缝前后频谱差异。
- 异常高频能量。
- 突发瞬态密度。
- 重复片段和潜在听觉疲劳特征。

自动 QA 只负责淘汰明显失败，不能替代人工听感和授权审核。

## 7. 当前项目差距

### 已具备

- `audio_stems` 授权与 QA 字段。
- `mixes.recipe_data` 多轨配方。
- AI Prompt 到草稿 Mix 的基本链路。
- 浏览器多轨预览。
- `ffmpeg` MP3 渲染和下载。
- 分享页、播放与收藏数据。

### 必须先修复

- `batch-04` 文件存在但没有接入 Seed。
- 音乐候选备注要求继续审核，但默认状态可能被标为 `approved`。
- 当前意图只有目标和环境，无法表达语言、人声密度、排除项和强度。
- 当前配方没有阶段、淡入淡出、Ducking、点缀事件和 Schema Version。
- TTS、上传、人声库部分仍是界面占位。
- Live Mix 和最终渲染的循环/事件语义尚未统一。

## 8. 重新排列后的执行方案

### Sprint 0：资产和规则止血，3–4 天

任务：

- 导出文件、Seed、数据库三方差异。
- 修正音乐候选 QA 默认状态。
- 决定 `batch-04` 的接入与淘汰。
- 从现有资产选出 18–24 个首发 Stem。
- 形成许可证快照和 Hash 清单。

验收：

- 每个 approved Stem 都能解释来源、授权和用途。
- 没有待审素材能够通过公开导出。
- 核心包可以覆盖三个一级目标。

### Sprint 1：无 AI 也成立的 Quick Create，5–7 天

任务：

- 建立三个一级目标和五个二级场景。
- 为每个二级场景制作两个默认配方。
- 首页只暴露目标、时长、是否人声和一句话描述。
- 在 3 秒级目标内返回 Live Mix 配方并开始播放。
- 提供环境/音乐/人声三个强度控制。

验收：

- 不配置任何外部 API 也能完成 10 个有效默认结果。
- 用户可以在一分钟内得到、调整并保存作品。
- 相同模板和随机种子可复现。

### Sprint 2：Recipe V2 与预览/导出一致，5–7 天

任务：

- 增加 `schemaVersion`、`phases`、`role`、Fade、Ducking 和 Events。
- 区分 Live Mix 与 Published Work。
- 增加版本冻结和确定性随机种子。
- 实现按素材配置的循环交叉淡化。
- 建立自动技术 QA 报告。

验收：

- Live Mix 与导出作品的轨道、阶段和事件一致。
- 10 个标准配方全部可渲染。
- 导出失败能够定位到素材、许可或技术原因。

### Sprint 3：受约束的引导人声，7–10 天（无人声 Beta 后置）

任务：

- 建立中英文两组脚本块。
- 支持脚本预览和用户编辑。
- 接入一个 TTS Provider Adapter。
- 保存句子级时间码、音色、模型、成本和授权信息。
- 人声阶段启用背景 Ducking。

验收：

- 睡前/夜醒、呼吸/放松两个脚本族可用。
- 中英文各至少两个审核音色。
- TTS 失败自动回退为无人声版本。
- 禁止表达测试全部通过。

本 Sprint 不属于 Voice-free Beta 发布范围。只有音色、节奏、停顿、混音与授权全部通过独立验收后，才允许设置 `GUIDED_VOICE_ENABLED=true`。

### Sprint 4：自然语言修改，5–7 天

只支持确定性操作：

- 某一层更大/更小。
- 替换或删除环境声。
- 去掉音乐或人声。
- 人声更慢、结束更早。
- 整体更温暖、更安静或更少变化。
- 延长时长和减少点缀。

验收：

- 未被指令涉及的轨道不改变。
- 修改可撤销。
- 不重复生成未受影响的人声资产。

### Sprint 5：后台资产工厂 Spike，5–8 天

任务：

- 从真实使用请求形成缺口排行。
- 只选择一个本地模型和一个外部音效/音乐 Provider。
- 每个缺口生产 4–10 个候选。
- 测量成本、延迟、可用率、循环处理结果和许可。
- 通过 QA 的候选才能晋升为公共 Stem。

继续条件：

- 候选人工可用率至少 30%。
- 新资产确实覆盖高频未命中请求。
- 许可支持组合、导出和公开分享。

未达到条件就采购或委托制作，不让模型实验阻塞产品。

### Sprint 6：小流量验证，至少 2 周

核心指标：

- Quick Create 到首播成功率。
- 从开始到听见结果的 P50/P95。
- 结果首次接受率，即不替换核心层就保存的比例。
- 每个 Stem 被使用和保留的次数。
- 局部修改率、保存率、导出率、分享率。
- TTS 成功率和单个已保存作品成本。
- 授权/QA 阻断率。
- 7 日内复听率。

先不把“生成次数”当成功指标。用户愿意保留、复听和分享，才说明配方有效。

## 9. 上线范围与商业化

### Free（Voice-free Beta）

- 三个一级目标。
- 基础核心 Stem。
- 有限作品数和时长。
- Live Mix、保存和基础分享。
- 无人声模式；生产人声通过后再作为后续能力开放。

### Pro

- 完整核心素材和高级模板。
- 更长作品和更多存储。
- 个性化 TTS 额度。
- 高级工作台和高质量导出。
- 分享页封面、数据分析和系列管理。

首版不把“实时生成新音乐”作为 Pro 的核心卖点。Pro 应先卖确定的价值：更好素材、更长时长、更可控人声、更专业分享和数据。

## 10. 决策门槛

只有数据满足条件后才增加复杂度：

| 候选能力 | 启动条件 |
| --- | --- |
| 更多核心 Stem | 高频请求内部未命中率持续超过 20% |
| 实时音乐生成 | 用户明确需要独特音乐，且愿意等待或付费 |
| 生物指标自适应 | Live Mix 留存成立且有明确设备场景 |
| 更多语言 | 目标语言请求量和付费信号明确 |
| 用户上传 | 版权、审核和存储流程成熟 |
| 声音克隆 | 获得明确同意、身份与滥用防护能力 |

## 11. 当前立即执行清单

下一轮开发只做 Sprint 0，不并行安装模型或接外部 API：

1. 生成资产审计表。
2. 修正音乐 QA 默认状态。
3. 接入或淘汰 `batch-04`。
4. 选定 18–24 个核心 Stem。
5. 建立三个目标、五个场景、十个默认配方。
6. 用当前渲染器批量渲染十个标准作品。
7. 人工试听并输出真实缺口。

Sprint 0 完成后，以真实缺口决定 TTS、采购和模型实验，不反过来让模型能力决定产品。
